# 電源状態遷移・低電池時動作仕様 — Draft v0.1
Updated: 2026-11-14 JST
Status: PROPOSED / TO_VERIFY — 設計方針案。閾値・実装・合格値は未確定。

## 目的
タイマー機能（進行状態・経過時刻）を優先し、高電圧表示は電力と安全上の従属負荷とする。試作したPWR/HV基板を完成品へ流用できるよう、モジュール間の停止仕様を定義する。

## 二層の状態機械
- **機能FSM**：IDLE / WORK / PAUSE / WORK_GRACE / BREAK / BREAK_END / SETTINGS。UIの意味は[ui-spec.md](ui-spec.md)を優先。
- **電源FSM**：BOOT_SAFE / NORMAL / POWER_SAVE / CRITICAL / SHUTDOWN / FAULT_LOCKOUT。
- 2つを分離する。例: WORK中でもCRITICALへ遷移可能。電源モードが変わっても、タイマーを自動的にPAUSEへ移すとは限らない。
- **優先順位**：ハード異常・過電圧などの安全停止 > 電池/温度保護 > タイマー状態の保存 > 低電力UI > HV表示/音。

## 電源FSM仕様
| 状態 | 進入条件案 | タイマー | HV_EN/HV5524 | OLED・通知 | 脱出条件 |
|---|---|---|---|---|---|
| BOOT_SAFE | 電源投入、MCUリセット | RTC/保存値と現在時刻から復元判定 | **ハードOFF / 全消灯** | 初期化が終わるまで表示最小限 | PWR良好、DRV初期化、OVP正常等の安全ゲート成立 |
| NORMAL | 電池/USB/SYS電圧、温度が動作範囲 | 通常 | ユーザー要求・表示状態に応じて起動 | 通常ポリシー | 低電力/異常検出 |
| POWER_SAVE | 電池電圧低下傾向、弱いUSB入力、SYS垂下など | 継続 | 点灯時間と同時点灯を削減、必要に応じOFF | 必要時のみ | 十分な回復または悪化 |
| CRITICAL | 電池保護の遮断前に低残量/過負荷を検出 | RTC基準で継続可能な限り継続、復元情報保存 | **OFF** | 警告を一時表示、以後節電 | 外部給電と十分な電源余裕の復帰、またはSHUTDOWN |
| SHUTDOWN | 動作電圧維持不可と予測、ユーザー電源OFF（方式未決） | 最終状態保存の後にMCU停止。RTC保持は回路/バックアップ次第 | **OFF** | OFF | 規定の再起動条件 |
| FAULT_LOCKOUT | HV OVP、充電温度異常、制御異常など | 異常種別に応じ継続または停止 | **ハードOFF・再起動禁止** | エラー提示可能なら短時間 | 原因解消と明示的復帰条件が揃うまでロック |

### 故障を別扱いする
- 高電圧過電圧：**MCUを経由しない独立監視→昇圧停止**。MCUが正常であれば故障記録を残す。
- 電池NTC異常：BQ25185自身の充電温度保護を第一層とし、必要ならシステム負荷も低減。ソフトのみを安全手段としない。
- 5V/3.3V brownout：MCU reset中のHV_ENがハードでOFFとなること。復旧後に無条件でHV再起動しない。
- USB脱着：グリッチ・反復reset・不意のHV再点灯がないか確認。
- HVコネクタ抜去：**電源OFF、放電済み、工具アクセスによる保守**。ホットプラグは禁止。

## 電池判定とセンシング
- 電圧のみからSOC（%）を正確に推定しない。低電池判定は**セル電圧・SYS・5V・充電状態・負荷・経過時間**を使って検討。BMS/電池パック保護の遮断は最後の安全保護であり通常停止点ではない。
- **電圧の閾値は未決定**。仮数値を基板回路へ書き込まない。電池メーカーの最小電圧、保護回路閾値、BQ25185 BUVLO、TPS61023入力条件、3.3Vレギュレータの保持条件、ADC精度、負荷時電圧降下、温度でGo/No-Go。
- ADCで電池電圧を測る場合、3.3V範囲への分圧、常時消費（分圧器のリーク）、測定タイミング、ADC基準、過渡保護を設計。XIAO RP2350のGPIOがSYS/BATへ直接接続されないこと。セル直結ADCはリセット/電源断時の逆給電にも配慮。
- しきい値の周囲に**ヒステリシスと持続時間**を設け、HV負荷切替による電圧ディップで状態が振動しないようにする。
- マイコンへの電源供給が止まってもRTCが動作するバックアップ経路があるか未確定。RTCは採用/実装/バックアップ仕様次第。**「電源断でも時刻管理が必ず継続する」は現時点では保証しない**。

## タイマーの復旧と記録
- エポック時刻ベースで、開始時刻・予定終了時刻・フェーズ種別・pause/graceとユーザー選択状態・連番/CRC等の整合性を記録する案。
- フラッシュへの頻繁な秒単位書込みは避け、**状態遷移時と安全な節目**に保存。突然の保護回路遮断時に最新状態を失う可能性は残る。代替としてRTCレジスタ/バックアップや外部FRAMを必要性・予算から比較（未採用）。
- RTCと保存内容の整合性が確認できれば再起動時に残り時間を再計算する。時刻不明、データ破損時は**勝手に次フェーズを開始しない**。ユーザーに確認を求める。
- WORK_GRACE/BREAK_ENDは従来の手動承諾方針を維持。USB抜去や電源復帰をフェーズ承諾として扱わない。

## 電源/表示の起動シーケンス（暫定）
1. 物理的なENデフォルトOFFで電源投入。OVP状態、各レール、電池温度/充電状態を取得。
2. HV5524を確実に全消灯状態へ初期化。5Vロジック・レベルシフタの通電順、GPIO浮遊時の挙動を検証。
3. 起動許可条件が満たされ、**意図された表示要求**がある場合のみHV_ENを有効化。
4. 停止時はカソード全OFF → HV_EN OFF → bleeder/放電を確認。**放電完了前の保守は禁止**。
5. OVPや過温などの独立ハード保護はファームウェアの制御要求に優先。

## 実装の最小追加要件
- PWR: BAT（または保護された測定点）とSYS/5Vの監視手段（必要性と分圧器電力を比較）、BQ25185 STAT信号、TS NTC、低電力状態で保持すべき負荷と遮断対象の分類。
- HV: HV_ENハードOFF既定、独立OVP、bleeder、LV/HVコネクタの隔離。
- CTRL: brownout設定、フラッシュ保存戦略、RTCの時間整合性確認、表示要求とHV許可を分離。
- ハードウェアのUVLO/保護設定の検証が終わるまで、ソフトウェアだけでLi-ionの過放電保護を成立させない。

## 試験計画と暫定合格観点
1. 可変電源で電池電圧を模擬し、軽負荷/通常/最大HV模擬負荷でNORMAL→POWER_SAVE→CRITICAL→SHUTDOWNを再現。
2. USB 500mA制限で充電中・負荷変動中のSYS/BAT/5VとMCU reset、HV_ENを同時観測。
3. HV有効中にUSB抜去、MCU reset、CTRLケーブル抜去（**LV信号のみ、HV側に触れない安全治具**）を模擬し、HV_EN OFF確認。
4. RTCと保存データの有無/破損を組合せて起動時のWORK_GRACE/BREAK_END等の自動遷移禁止を確認。
5. 温度・電池電圧・ドライバOVPの異常注入は教員の安全レビューの下、制御端子・ダミー負荷から実施。高電圧の露出試験や故意の電池故障を行わない。
6. **数値の合格基準（電圧閾値、応答遅延、放電時間、温度上限、回復時間）は今後回路仕様とメーカー定格から決定**。
