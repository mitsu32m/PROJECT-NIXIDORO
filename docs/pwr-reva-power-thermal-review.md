# PROJECT-NIXIDORO PWR Rev.A v3 電力・起動・熱検証

2026-11-14。**設計モデルであり実機保証ではない。** [統合ネット仕様](https://github.com/mitsu32m/PROJECT-NIXIDORO/blob/codex/pwr-reva-v3-review/docs/reva-integrated-net-spec.md)、PWR v3 KiCad回路図・ネットリスト、およびメーカー資料を照合した。HV基板、CTRL基板、セル、配線、筐体の実測値は未取得。数値表の再計算結果は`power-model.csv`、式は`power-model.py`に保存した。

CSVの`simple_current_pass`はUSB要求≤450 mAかつ、電池使用時は27°CのOCP精度から計算した**参考下側2.56 A未満**だけを表す。セル、熱、起動、高電圧安全の合否ではない。

## 判定

**現行構成は条件付き成立の候補。最悪負荷の成立は未証明。USBのみ・500 mA設定で205 V×16 mAは不成立。** 電池ありでも、低電池・効率低下・OLEDと音声同時使用では電池過電流と熱の余裕が不足する。MAX668用変圧器の個別仕様、5 Vインダクタの実型番、実効容量、セル内部抵抗、基板放熱が未確定なので、連続16 mAと充電中のHV起動を承認できない。これらの実測で下記条件を満たせなければ、USB入力電流設定・電源分配・HV負荷方針を含めアーキテクチャ変更が必要。

## 計算式と仮定

- `P_HV=V_HV×I_HV`、`P_5V=P_HV/η_HV + P_5Vlogic`、`P_SYS=P_5V/η_61023 + P_SYSother`。
- `I_L,DC=P_5V/(η_61023×V_SYS)`、`D≈1−η_61023×V_SYS/5`、`ΔI_L≈V_SYS×D/(L_min×f_SW)`、`I_L,peak≈I_L,DC+ΔI_L/2`。TIの式5～7に準じた一次近似。L_min=0.7 µH（1 µHの−30%）、f_SW=1 MHz（VIN>1.5 V）とした。パルス起動、インダクタの飽和によるL低下、スイッチング損失は含まない。
- 電池のみ: `V_SYS≈V_BAT−I_BAT×R_path`、`P_SYS=V_SYS×I_BAT`。USB＋電池補助: `P_SYS≈V_SYS×(I_USB+I_BAT)`。`R_path=0.14 Ω`はBQ BATFET最大値を仮置きしたもので、**セル・保護FET・接点・配線抵抗は未加算**。このため低電池結果は楽観側になり得る。
- USBは5.0 V、`I_USB=0.45 A`を保守側の上限として使用。USBのみの4.5 V×0.45 A=**2.025 Wは理想的なSYS側上限**であり、実際の電圧降下・BQ自己消費で減る。モデルのUSB過負荷行は安定動作電圧を出さず、必要電流だけ示す。
- `P_5Vlogic=0.50 W`（HV5524・シフタ等の負荷上限を未測定のため仮置き）、`P_SYSother=0.50 W`（Pico 2、OLED、RTC等。OLEDは[Adafruit #938](https://www.adafruit.com/product/938)が平均40 mA@3.3 Vと記載）、音声同時時は+0.80 W（アンプ入力の仮置き）。[TPA2005D1](https://www.ti.com/lit/ds/symlink/tpa2005d1.pdf)の1.4 Wは5 V/8 Ω・THD10%での**音声出力**条件で、SYS入力0.8 Wの保証ではない。実装条件がそれ以上なら再計算する。
- `η_HV=0.60/0.70/0.80`、`η_61023=0.80/0.85/0.90`をストレス/作業/楽観の感度分析に採用。0 mA時は効率式が無意味なので、HVコントローラ待機等の仮の5 V消費0.02 Wを加えた。効率は実測で置換する。

## 起動余裕と電流限界

TPS61023の0.5 Vは稼働範囲の下限であり、**起動保証として使う値は1.8 V**。ただし1.8 Vで最大負荷を起動できる意味ではない。起動時の350 mAプリチャージと700 µsはTIの特定無負荷条件である。PWRの5 Vロジックを初期負荷としても安全か、C5/C6の実効容量、HV側入力容量、SYSディップを試験する。HV基板のENは5 V安定とPico起動後までLOWを維持する。HV出力コンデンサの蓄積エネルギーは`E=½C_HV V²`（例: 1 µF・200 Vなら20 mJ）。実C_HVと充電時間が未確定なのでHV起動ピークは計算確定できない。

ストレス仮定の電池3.3 V＋音声、205 V/16 mAでは`V_SYS=2.87 V`、`I_L,DC=2.60 A`、L_min=0.7 µHのリップル約2.22 A、**ピーク約3.71 A**。valleyは約1.49 Aで、TIの2.7 A最小valley制限を定常式上は超えない。ただしL1実物のIsat/温度降下、突入と負荷ステップは別で、**1 µHという値だけで設計可としない**。TI推奨1 µH品の例にはIsat 7～9.6 A、DCR最大9.78～13.5 mΩがあるが、v3のL1には実型番もフットプリントも未割当。ピーク3.71 Aに20%設計余裕を置けば、少なくとも4.45 A以上を実温度・L低下で満たす候補を選ぶ必要がある。20%は設計仮定で、十分性を実験で確認する。

TIのvalley式に最小2.7 Aを入れた理想上限は、この条件で`I_5V,CL≈(1−D)(2.7+ΔI_L/2)≈1.75 A`。要求1.19 Aより大きいが、**熱、入力の電圧降下、起動負荷を含む保証最大出力電流ではない**。電池電圧がさらに下がると上限と効率が低下し得る。

## 暫定ファームウェア条件と実験ゲート

1. 起動時は`PWR_5V_EN=LOW`、`HV_EN_REQ=LOW`、アンプSHUTDOWN。Pico起動後にADCを測り、5 Vを先に起動、5 Vが安定してからHVを段階的に起動する。`PWR_5V_OK`は未実装なのでADC_5Vとタイムアウトを暫定監視とする。HV独立OVPとハードOFF既定は必須。
2. **電池なし、電池電圧不明、ADC異常、SYS低下中はHV禁止。** USBのみ500 mAでは最大負荷は成立しない。試験前の暫定ゲートは無負荷VBAT≥3.8 V、HV投入中SYS≥3.4 V、5 V≥4.8 V。これらは安全保証の閾値ではなく、セル・Schottky・電圧誤差・過渡を測って確定する。
3. HV起動中は充電電流を期待しない。音声を停止し、OLED全点灯やHV全灯パターンを抑え、段階的に負荷を増す。ベンチ確認までは**HV電流8 mA相当以下の表示パターン**に限定し、16 mAはダミー負荷でのストレス試験として扱う。ファームだけではHV電流の実値は分からないため、表示パターン制限は実測と対応付ける。
4. HV動作中にVBAT/SYS/5 Vが閾値を下回る、FAULT_Nが有効、Picoリセット、温度異常なら直ちにHV要求をLOWにし、再起動はヒステリシスと待ち時間を設ける。ソフト停止は独立のHV過電圧保護・放電の代わりにならない。
5. 試験はセル模擬・電子負荷から始め、USBのみ/電池のみ/両方、充電中、3.3/3.6/4.0 V電池、HV 0/4/8/12/16 mA、音声・OLED同時、起動/切断/故障を測る。IIN、IBAT、VSYS、5 V、L1電流波形、BQ/U2/L1/HV段温度を記録。**定常と過渡の双方で**セル保護・BQ制限・L1 Isat・125°C TJを満たしてから最大負荷を解禁する。

PWR KiCadの回路ネット・部品定数自体に今回の検証で確定できる変更はなかった。J3 pin10=`ADC_SENSE_EN`はv3ネットリストに存在し、GP17割当とJ3 10極を統合仕様・ピンマップ・インターコネクト資料に反映する。CTRL/HV回路図とファームは未実装。PCBレイアウト、ガーバー、部品発注は行わない。
